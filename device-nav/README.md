# 每设备自己的导航页 · device-nav

> 每台设备跑一个自己的页面，只列**这台设备**上正在跑的网站。手机 / iPad 打开 `http://<本机IP>:8000` 就能点进去，不用记端口，也不需要 Mac 统一扫描。

> [工程] 零第三方依赖：Python 3 标准库 + 单文件 HTML。状态：2026-11-27 新建，替代 `lan-nav/` 的集中式扫描方案。

---

## 1. 为什么改成每设备一页

旧的 `lan-nav/` 是「Mac 当中心，每台设备跑 9700 代理，Mac 每 120 秒扫全网的 9700」。实际排查下来，问题集中在跨设备链路上：

- Mac 的扫描器要能发现设备、设备防火墙要放行 9700、代理要在 8 秒内返回，任何一环出问题整台设备就消失；
- 设备上的服务清单本来只有本机最清楚，绕一圈交给 Mac 反而增加故障点；
- 新设备接入要复制 agent、开端口、等扫描，不适合「随手开个服务就想用手机看」。

新方案把职责收敛到一台设备内部：

```
手机 / iPad
    │  http://192.168.31.22:8000
    ▼
┌──────────────────────────────┐
│ 这台设备上的 server.py        │
│  ├─ 自动探测本机 HTTP 服务    │
│  └─ 读取 sites.json 手工入口  │
└──────────────────────────────┘
```

没有中心、没有网段扫描、没有 9700 注册协议。每台设备只对自己负责；想看另一台设备的服务，就在自己的页面里加一条手工入口（或直接打开那台设备的页面）。

---

## 2. 角色与文件

| 文件 | 作用 |
|---|---|
| `server.py` | 静态页面 + 本机服务探测 API + 手工入口保存 API |
| `detect.py` | 只探测本机监听端口，判断是否 HTTP、抓 `<title>` |
| `index.html` | 导航页：本机服务 / 常用入口 / 正式版 / 测试版 / 实验项目 |
| `edit.html` | 浏览器里增删改手工入口 |
| `sites.json` | 手工入口数据源（NAS、路由器、其他设备） |
| `services.json` | 可选：按端口覆盖自动发现的名称 / 备注 / 标签，或屏蔽端口 |
| `start-device.bat` | Windows 一键启动 |
| `start-device.command` | Mac / Linux 一键启动 |

运行时不需要 `agent.py`、`discover.py`，也不需要改 Mac 上的任何文件。

## 3. 快速开始

### Windows

1. 把整个 `device-nav/` 目录放到本机，例如 `C:\Users\<用户>\device-nav\`。
2. 双击 `start-device.bat`，保持命令行窗口开着。
3. 浏览器打开 `http://127.0.0.1:8000/`；手机 / iPad 打开 `http://<本机内网IP>:8000/`。

首次运行 Windows 可能弹出防火墙提示，选「允许访问」（专用网络）。如果页面能打开但手机打不开，优先检查这一项。

### Mac / Linux

```bash
chmod +x start-device.command
./start-device.command
```

也可以直接运行：

```bash
python3 server.py
# 或指定端口
PORT=8001 python3 server.py
```

### 验证

```bash
curl http://127.0.0.1:8000/api/services
curl http://127.0.0.1:8000/api/sites
```

`/api/services` 返回 `device`、`ip`、`port`、`updatedAt`、`services[]`。`services` 是数组，里面每个元素含 `name` / `url` / `desc` / `tag` / `port` / `title`。

## 4. 页面分组

| 分组 | 来源 | 说明 |
|---|---|---|
| 本机服务 | 自动探测 | 这台设备上监听 `0.0.0.0` 或内网 IP 的 HTTP 服务 |
| 常用入口 | `sites.json` | NAS、路由器、其他设备的固定地址 |
| 正式版 | `sites.json` | 稳定可用的项目 |
| 测试版 | `sites.json` | 联调 / 验收环境 |
| 实验项目 | `sites.json` | 随手搭的小玩意 |

「本机服务」始终显示；其他分组有内容才显示。如果一条手工入口都没有，页面会出现一个「手工入口」空卡片，点进去就是编辑页。

---

## 5. 自动发现规则

`detect.py` 每次被请求时做这些事（结果缓存 3 秒）：

1. 用 `netstat -ano -p TCP`（Windows）/ `lsof`（macOS）/ `ss -ltn`（Linux）列出本机监听中的 TCP 端口。
2. 只保留绑定 `0.0.0.0`、`*`、`[::]` 或**本机内网 IP** 的端口；只绑 `127.0.0.1` / `::1` 的会被排除（手机连不上）。
3. 对候选端口并发发一个 HTTP GET，确认它说 HTTP，并抓 `<title>` 作为默认名称。
4. 用 `services.json` 覆盖名称 / 备注 / 标签，或屏蔽端口。
5. 返回 JSON。

**默认过滤**：

- 屏蔽本页自身端口（默认 8000）和旧的 9700 代理端口；
- 屏蔽 `50000–59999`（编辑器 / 工具内部服务），需要时用 `DEVICE_NAV_ALLOW_HIGH_PORTS=1` 放开；
- 屏蔽返回 403 且无 `<title>` 的系统服务；
- 只上报 HTTP；数据库、SSH 等纯 TCP 不会出现；
- **不扫描网段，不访问其他设备**。

## 6. 配置

### 6.1 `services.json`：改自动发现的名称 / 标签 / 屏蔽

文件是**数组**，每项按端口匹配：

```json
[
  {
    "port": 3000,
    "name": "订单系统后台",
    "desc": "正式版，主项目",
    "tag": "正式"
  },
  {
    "port": 8080,
    "enabled": false
  },
  {
    "url": "http://192.168.31.111:5000",
    "name": "NAS",
    "desc": "群晖 DSM",
    "tag": "外部"
  }
]
```

| 字段 | 作用 |
|---|---|
| `port` | 按端口匹配一条自动发现的服务 |
| `name` / `desc` / `tag` | 覆盖自动抓取的名称、备注、角标 |
| `enabled: false` | 屏蔽该端口 |
| `url` | ① 有 `port` 时覆盖上报地址；② 无 `port` 时追加一条固定入口 |

改完不需要重启，最多 3 秒生效。JSON 必须是合法数组；格式错误时按空配置处理（不会崩，但覆盖会失效）。

### 6.2 `sites.json` / 编辑页：手工入口

浏览器打开 `http://<本机IP>:8000/edit.html`，增删改后点「保存到本机」。数据写到 `sites.json`：

```json
[
  {
    "group": "basics",
    "name": "NAS",
    "url": "http://192.168.31.111:5000",
    "desc": "群晖 DSM · EzioNas.local",
    "tag": "固定 IP"
  },
  {
    "group": "production",
    "name": "订单系统",
    "url": "http://192.168.31.22:3000",
    "desc": "正式版",
    "tag": "正式"
  }
]
```

`group` 只能是 `basics` / `production` / `testing` / `lab`。名称和地址不能为空，地址必须以 `http://` 或 `https://` 开头。

如果手工入口和自动发现是同一个 URL，页面会优先显示手工入口，避免重复卡片。

### 6.3 端口与编辑口令

默认端口 8000；如果 8000 已被其他开发服务占用，`server.py` 会自动尝试 8001–8019，并在终端打印实际端口。也可以手动指定：

```bash
# 换页面端口
PORT=8001 python3 server.py

# 给编辑页加口令（保存时需在编辑页输入）
NAV_EDIT_TOKEN=your-token python3 server.py
```

Windows 可在启动前设置环境变量：

```bat
set PORT=8001
set NAV_EDIT_TOKEN=your-token
start-device.bat
```

## 7. API

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/services` | 本机服务清单；`?refresh=1` 跳过 3 秒缓存 |
| `POST` | `/api/refresh` | 强制重新探测，返回 `{ok, count, updatedAt}` |
| `GET` | `/api/sites` | 读手工入口数组 |
| `POST` | `/api/sites` | 保存手工入口数组；有 `NAV_EDIT_TOKEN` 时需 `X-Token` 头 |
| `GET` | `/api/config` | 返回 `{auth, device, ip, port}` |

`/api/services` 返回示例：

```json
{
  "device": "nanami",
  "ip": "192.168.31.22",
  "port": 8000,
  "updatedAt": "2026-11-27T00:20:00",
  "services": [
    {
      "name": "视频库 · 局域网",
      "url": "http://192.168.31.22:8765",
      "desc": "192.168.31.22:8765",
      "tag": "本机",
      "port": 8765,
      "title": "视频库 · 局域网"
    }
  ]
}
```

## 8. 与 `lan-nav/` 的区别

| 项 | `lan-nav/`（旧） | `device-nav/`（新） |
|---|---|---|
| 拓扑 | Mac 中心 + 每设备 9700 代理 | 每设备一个独立页面 |
| 跨设备 | Mac 扫全 `/24`，汇总到一页 | 不聚合；需要时手工加入口 |
| 端口 | 设备端 9700 + Mac 8000 | 每设备 8000（可改） |
| 依赖 | 设备代理、Mac 扫描器、防火墙放行 9700 | 只需要本机 Python |
| 故障面 | 设备发现、9700 可达、8 秒超时、Mac 扫描线程 | 本机端口探测 + 页面服务 |
| 适合 | 想在一个页面看所有设备 | 每台设备自己的服务自己维护 |

`lan-nav/` 保留作为历史实现和集中式方案的参考，不再推荐新部署。

## 9. 排障

| 现象 | 原因与处理 |
|---|---|
| 页面打不开 | `server.py` 没启动、端口被占、防火墙拦了页面端口。换端口用 `PORT=8001 python3 server.py` |
| 页面能开，手机打不开 | 手机不在同一 Wi-Fi；Windows 防火墙没放行 Python；页面绑定的是 `0.0.0.0`（默认已是） |
| 「本机服务」为空 | 服务只绑了 `127.0.0.1`；端口在 50000–59999；不是 HTTP；或服务刚启动还没监听。让服务监听 `0.0.0.0` 后点刷新 |
| 服务有了但名称是 IP:端口 | 页面没有 `<title>`。在 `services.json` 里按端口写 `name` |
| 服务不想显示 | 在 `services.json` 里给该端口加 `"enabled": false` |
| 改了 `services.json` 没生效 | JSON 格式错误（按空配置处理）；或还没过 3 秒缓存 |
| 编辑页保存 401 | 启动时设了 `NAV_EDIT_TOKEN`，在编辑页输入口令；口令存在浏览器 localStorage |
| 保存后页面没变 | 页面 20 秒自动刷新；点右上「刷新」可立即更新 |
| 端口 8000 被占 | 默认会自动改用 8001–8019；也可 `PORT=8001` 手动指定。页面里的地址会自动用实际端口 |

## 10. 安全与边界

- 页面默认绑定 `0.0.0.0`，同一局域网内可访问；不要把端口转发到公网。
- 没有编辑口令时，局域网内任何人都能改手工入口。需要时设置 `NAV_EDIT_TOKEN`。
- 探测只读取本机监听端口和 HTTP `<title>`，不采集页面正文、不写访问日志（`DEVICE_NAV_DEBUG=1` 时才输出请求行）。
- 不做网段扫描，不读取其他设备；每台设备的数据只在本机。
- 默认不自动开机启动；长期使用把 `start-device.bat` 快捷方式放进 Windows「启动」文件夹，或用 launchd / systemd。
