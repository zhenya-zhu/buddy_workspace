## 1. 产品切入与这次修订 [推断]

**候选切入：帮助英语开发者/远程工作者，在一次电脑工作间歇中选择一项可执行的、经审核的日常活动，并逐步建立愿意重复的休息习惯。**

候选差异是减少选择负担、降低开始成本、保留可理解的体验记录。是否优于收藏视频、普通休息计时器或纸笔日志，必须靠目标用户验证。个人康复经历能帮助提出问题，不能证明一般消费者都有相同需求。

首发仍需确定一个实际服务国家/地区。英语是语言选择，不是法规辖区；全球定位保留在市场愿景中。

本轮收缩：原有 A/B/C 三种文案保留为假设库，**第一轮只运行两种**；5–8 项活动是后续 MVP 候选规模，Phase 0 允许只开放一项已审核活动。核心闭环先简单做通。

## 2. 三类页面，各自有明确任务

| 层 | 用户来到这里要什么 | 页面应交付什么 | 主要衡量 |
|---|---|---|---|
| SEO 场景内容 | 了解某个工作情境或日常活动问题 | 直接回答、示例、限制、来源、相关可选体验 | 合适搜索流量及进入体验后的行为 |
| 定位实验落地页 | 快速判断产品是否值得尝试 | 一句明确承诺、真实体验预览、适用范围、一个主 CTA | 开始率与后续完成/复用，不只点击 |
| 共享 Web 体验 | 马上完成一件小事 | 简单选择、适用范围提示、审核内容、反馈与恢复入口 | 完成时间、独立完成、到期返回、可交付成本 |

用户从 SEO 内容可以直接进入体验，不需要再过一层广告落地页。实验落地页主要承接招募或受控推广；它不是天然的 SEO 页面。

**“很多入口，共享一套 system”是可行方向；共享的首先是任务与规则，不是要求首日就做复杂推荐系统。**

## 3. 首次体验与次日体验 [推断]

| 步骤 | 用户看到/做什么 | UX 要求 | 观察信号 |
|---|---|---|---|
| 入口 | 一个具体场景与“试一次”的按钮 | 说明约需时间、是否需器材；不先要求下载或注册 | 是否理解下一步与产品边界 |
| 目标 | 选择今天想完成的工作间歇任务 | 沿用入口意图作为可修改默认值；只问影响内容选择的问题 | 不重复填写；用户能修改 |
| 适用范围 | 简短说明与必要安全问题 | 是/否/不确定均可；风险或不确定走退出帮助；通过不等于医学安全保证 | 能正确退出、不被逼着继续 |
| 首次行动 | 一项已审核活动及可选基线 | 一个主动作、清楚示范、停止按钮；未审核则用非运动记录原型 | 无人提示能否完成 |
| 当次反馈 | Easier / Same / Worse / Unsure | 中性呈现全部选项；更差进入停止帮助，不再自动加动作 | 完成与反馈分开计数 |
| 保存与返回 | 自愿保存记录、选择提醒 | 首次价值之后再请求必要联系方式或权限；说明人工服务范围 | 真实次日返回，区别于口头意愿 |
| 七天回顾 | 已完成、未做、缺失、暂停与自评记录 | 如实显示变化，不推断病因或推荐“最有效治疗” | 用户是否据此决定保留某个习惯 |
| 付费延续 | 明确的后续记录/习惯支持服务 | 期限、内容、价格、退款、人工部分一并展示 | 真实付款、交付成本与退款 |

约 3 分钟是首访可用性目标，不是疗效承诺；不为达成时间目标压缩必要安全信息。用户可跳过量化基线；此时报告不生成前后分数差。

次日不要重走首次问卷：恢复上次任务 → 简短回顾 → 判断继续/暂停 → 用户主动操作。没有反馈时不自动推断改善、升级难度或换新动作。

## 4. 快速实验与 SEO 长期内容分开

### 文案实验 [推断]

初轮建议 A“电脑工作后的肩颈僵硬情境”与 C“容易坚持的工作间歇活动”；B“观察活动体验”作为下一轮。都不承诺治疗。先检查受众能否理解，再测试转化。

每轮固定人群、服务和安全内容，只改变一个主要定位假设。若同时修改标题、配图和解释，应称为定位方案比较，不能归因到某个单词。低流量期做定性访谈与描述性漏斗，不宣布统计赢家。

### 索引策略 [原文 S1、S2；具体应用为工程设计]

| 页面情形 | 处理 |
|---|---|
| 为招募新建、从不计划参与搜索排名的实验页 | 可用 noindex，不进 sitemap；不从既有 SEO 页把搜索流量统一重定向到它 |
| 已索引页面进行多个 URL 的 A/B 测试 | 按 Google 指南用 canonical 指回原页面；需要跳转时用临时 302，结束后清理 |
| 正式独立场景页 | 稳定 URL、自引用 canonical、独立有用内容与内链 |
| 个人会话/结果页 | 访问控制 + noindex + 谨慎缓存；noindex 不是隐私保护 |
| 只换病名/肌肉名，正文近似且都导向同一入口的批量页面 | 不发布为 SEO 页面；不能用页面数量代替需求满足 |

不能把 canonical 与 noindex 当作可随意互换的按钮。面向人和搜索引擎的内容保持一致。健康内容的作者、审核、来源和更新时间应真实可查，但这些并不保证排名。

## 5. 最小功能与未来系统 [工程]

**现在**：一个站点、一种语言、一个核心流程、少量审核内容、轻量恢复记录、人工报告。内容端与体验端共用活动 ID 和审核版本，用户无需知道内部实现。

**以后再做**：在确有重复选择需求后，增加经审核的规则配置、更多活动和偏好；在内容维护成为真实瓶颈后再建 CMS；在 Web 无法满足持续使用时再建原生 App。

推荐逻辑只使用实际必要的日常目标、时间、器材与用户选择。安全规则在先，候选内容过滤在后，最终展示可解释。不能根据“某处痛 + 按了舒服”生成肌肉病因，也不能因用户选择某症状就自动切换为专业治疗方案。

## 6. 漏斗定义与隐私 [推断 / 工程]

产品数据默认在受控的一方系统中计算去标识汇总；即使事件没有姓名，活动类别、健康站访问与安全退出也可能透露健康兴趣或状态。未经适用地区审核，不向广告平台传送这些事件或据此建立再营销人群。

| 指标 | 分子 / 分母 | 解释限制 |
|---|---|---|
| 开始率 | 去重开始人数 / 同渠道去重入口访问者 | 点击不能代表获得价值 |
| 首次完成率 | 完成一次行动并提交反馈者 / 选择进入且符合该流程适用范围者 | 同时报告所有开始者、退出、跳过与缺失，避免隐藏流失 |
| D1 返回 | 在预定次日窗口完成 check-in 者 / 已到该观察窗口的首次完成者 | 窗口按用户当地日期预先固定；尚未到期者单列 |
| 持续记录 | 七天窗口内至少五个不同日完成 check-in 者 / 已完整经过窗口的入组者 | 记录与实际活动次数分别报告；安全退出不可抹除 |
| 付费转化 | 成功付款的去重人数 / 实际见到同一报价的合适用户 | 退款、取消、履约成本并列 |
| 安全与信任护栏 | 停止/恶化报告、错误继续、删除失败、投诉的数量与分母 | 没有事件不等于证明安全；不为转化降低退出率 |

建议的早期价值指标是“每周有多少目标用户主动完成并记录多次工作间歇”，频次标准待探索；不使用“疗效提升率”作产品北极星指标。七天记录是描述性观察，不是可证明某动作因果疗效的 N-of-1 试验。

## 7. 全球产品边界如何落到流程 [推断]

“没有诊断功能”仍不足以保证全球合规。FDA 2026 年 general wellness 文件同时涉及疾病的治疗、缓解、预防等预期用途；它也不是其他国家的通行许可。[原文，S4]

上线评审对每个首发市场记录：实际功能、预期用途、公开文案、动作推荐方式、数据类型与处理者、消费者条款/收款、审核责任人、证据与通过/待定状态。需要当地专业判断的项目交由相应专业人员确认，不在本文件宣布产品分类。

UX 中禁止“检查通过=没有疾病”“动作有效=解开粘连”“填写症状=获得个性化康复处方”。营销页、结果页、通知与应用商店描述遵循同一边界。免责声明不能修复与实际功能相矛盾的定位。

首发国家、临床内容、隐私机制与付款交付均未完成审核；现在可以设计和验证非运动原型，真实服务按通过的范围逐步开放。

## 8. 本轮最小执行顺序 [推断]

1. 8–12 次目标用户问题访谈：最近一次困扰、实际尝试、为什么没坚持、愿投入什么；与关键词/SERP 调研并行。
2. 两种定位文案 + 一个非运动核心原型，先找 5–8 人检查理解和操作。
3. 对具体活动、示范、规则、服务地区与数据做审核；先放一项即可。
4. 以人工方式招募 20–30 人做七天观察；完整观察期随最后入组者顺延。
5. 交付报告并测试一个清楚可交付的付费方案；候选价格不是验证结果。
6. 复盘瓶颈，决定自动化什么；留存未明时不扩动作数、国家或原生 App。
