# 两周 Concierge 实验与商业验证计划（M0 → M2）

> **状态**：待执行的实验方案，不是研究结果或临床试验。  
> **日期**：2026-10-28；基于「康复」Project 2026-09-24 历史讨论摘要，[既有讨论] 已注明；[新增工程/产品建议] 为本次落地设计。  
> 关联：[产品策略](./product-strategy.md) · [MVP PRD](./mvp-prd.md) · [SEO 首站路线图](../../frontend/development-roadmap.md)。

## 1. 要验证的核心假设

| 假设 | 观察什么 | 什么不是证据 |
|---|---|---|
| H1 用户有真实需求 | 有目标用户进入并完成 3 分钟体验，且说得出具体工作情境 | 仅广告点击 / 口头点赞 |
| H2 低摩擦小活动有价值 | 用户愿意次日回来，主观记录是否有用途 | “做了一次感觉好些”=治疗成功 |
| H3 7 天追踪比单次视频有价值 | 有人持续 ≥5 天、查看报告并能说明其价值 | 仅一次注册 |
| H4 用户愿意付费 | 真正付费购买受明确定义的 28 天服务 | “我可能愿意付费” |
| H5 可安全运营 | 经审查内容、风险退出逻辑与用户退出机制可执行 | 仅贴一段免责声明 |

**这些指标只是早期启发式决策线，不具有统计显著性，也不能用于证明医疗有效性。**

## 2. 受众与招募 [既有讨论]

- 总目标：**20–30 位**能用英语交流的屏幕工作者，优先开发者/远程工作者，愿意尝试七天短时活动反馈；**先招 5–8 人验证可用性，再扩到剩余 15–20 人**。
- 招募：合法合规的小型开发者社区、远程工作社群、同事/朋友转介绍、自有 landing 页。不得假冒医生/患者、制造临床诊断承诺或在禁止推广的社区刷帖。
- 排除/停止：临床审核后的安全筛查触发退出；不收集或公示个人诊断史。参与同意、数据隐私和退出随时可用。
- 必须记录来源渠道，区分熟人样本和真正冷启动访客，避免误判 SEO 产品需求。

## 3. 3 landing × 同一体验 [既有讨论]

| Variant | 标题 | CTA | 核心问题 |
|---|---|---|---|
| A | Neck stiffness after working at a computer? | Try a gentle desk check-in | 是否对具体问题定位敏感 |
| B | Find movement breaks that work for your body | Start a 7-day exploration | 是否看重观察与反馈 |
| C | Build a desk movement routine you’ll actually repeat | Try a 2-minute break | 是否看重坚持习惯 |

实验使用同一产品流程，不要给不同分组提供不同动作规则。确保任何 landing 都写清限制、风险和适用范围。对外 SEO 页面必须有独立内容价值；纯测试变体使用 noindex/canonical/受控流量，不通过复制关键词页人为放大索引量。

### Phase 0 核心流程（首访）

Landing → 选一个日常目标 → 安全检查 → 主观基线 → **经审核的** 2 分钟活动 → Easier/Same/Worse/Unsure → 次日意向。无临床审阅时，只测前面的非运动环节与 copy，不执行动作体验。

### 七天 Concierge（首访后）

每天用户自愿反馈今日状态与上次活动体验；观察员按**经临床审核的有限规则**选择继续、暂停或建议专业帮助；不自行根据症状进行医学诊断。第 7 天由人工整理数据观察摘要。

**每次服务留记录**：session ID、观察员 ID、规则/动作版本、接触时间、活动是否执行、是否中止、是否出现需要安全处理的情况；敏感内容不放公开仓库。

## 4. 可执行时间安排（建议的两周，不是交付时间承诺）

| 窗口 | 要做什么 | 验收产物 |
|---|---|---|
| Day 1–2 | 完成文案、招募说明、同意和隐私材料、临床审核计划；搭建不含医疗指导的简版 landing/体验 | 3 套文案、信息说明、未审核活动被封闭 |
| Day 3–4 | 5–8 位目标用户做可用性测试（录制仅经明确许可，默认不录） | 完成时间、卡点、退出原因、理解偏差清单 |
| Day 5–7 | 修复卡点，按审核结果启用 5–8 个活动或保持纯观察模式；启动招募至总量 20–30 | 参与者去标识记录、版本化的活动库 |
| Day 8–13 | 人工七天跟踪、次日提醒（明确 opt-in）、每日记录 | D1/D3/D7 留存与安全事件日志 |
| Day 14+ | 对已完成七天的参与者交付免费报告，并测试真实付费；逐项做 go / iterate / stop 决策 | 数据表、访谈主题、收款证据、风险评估 |

注意：后入组者的第七天可能落在 Day 14 之后，不能为了让项目“恰好两周结束”缩短观察周期。完整测试会因招募节奏顺延。

## 5. 建议决策门槛 [既有讨论 + 新增可操作定义]

以下数值**来自先前讨论的早期参考阈值**，只用于“继续迭代还是停止投入”的方向判断，绝非医疗功效或统计显著性结论。

| 指标 | 候选判断线 | 分母与证据 | 如果不足 |
|---|---|---|---|
| 首访独立完成 | 大多数测试用户能够无引导完成 | 5–8 位可用性测试的现场记录 | 减少步骤/优化文案 |
| 愿意次日再试 | ≥50% 首访完成者选择 Yes | next_day_opt_in / 首访完成数 | 测试价值主张和提醒设计 |
| 七天持续 | **6–8 人**实际完成 **≥5 天**（在 20–30 人招募目标下） | 以每位参与者有可核对的每日记录为准 | 研究用户为什么没回来；不要加功能掩盖问题 |
| 实际付费 | **2–3 人真实付款** | 完成试验者的实际成功支付、去重人数 | 明确价值/价格/服务交付，不把兴趣当销售 |
| 安全 | 不出现可归因于流程的明显安全异常；任何严重事件触发立即暂停复盘 | 完整事件和退出审计 | 立即暂停有风险流程、寻求医学审阅 |

**付费价格实验**：[既有讨论] $9 / $19，提供明确定义的 28-day adaptive desk mobility experiment。确保对外明确由人工与固定规则支持的服务范围、时间、退款与适用地区；支付能力未完成前只能询问意向，**不得把意向记成实际付款**。对首批受试者不必复杂 A/B 随机分组，可先检查清楚承诺和支付安全；记录展示过哪个价格。

“至少 2–3 付费”只有在真的提供了可交付服务、用户知晓限制且允许退款的情况下才有意义。若没有医学审阅，不应售卖个性化康复处方。

## 6. 最小实验数据和分析

核心漏斗按**去重参与者**：landing_view → start_clicked → safety_completed / safety_exited → baseline → reviewed_activity_started/finished → immediate_feedback → next_day_return → ≥5 day completion → report_viewed → checkout_success。

日报字段：日期、匿名 session、source/variant、是否完成、是否返回、功能目标分类、当天是否记状态、是否活动、是否反馈、观察员操作、变更原因、是否出现风险退出。**医学/症状详情不发送第三方普通网站分析工具**；敏感记录在受控私有存储，限权限和期限。

数据报告必须同时包含：
- **样本构成/招募渠道**（朋友/社区/自然流量）
- **分子、分母和缺失数据**，不只给百分比
- **提前退出和 adverse/safety events**
- **价格曝光与实际成功付款**（如支付尚未集成注明未验证）
- **访谈的反例/负面反馈**，不得只展示成功个例

## 7. Go / Iterate / Stop 决策

**Go（继续做可公开试用的 Web MVP）**：用户能独立完成、达到核心留存参考阈值、无阻断性安全风险，且有真实付款/明确可重复的需求信号；并补足 SEO 关键词与法规验证。符合几个指标不自动证明产品市场匹配。

**Iterate（优化一轮）**：有初次体验兴趣但日次回访差；或留存很好但价格/价值表述不清；需识别是问题定位、流程摩擦、提醒、活动质量还是服务成本。

**Stop/Pivot（收缩）**：目标人群无法说明需求、体验流程无法安全运行、风险管理不可行、无法形成持续回访，或需要过多人工专业介入才能交付，经济性不成立。

**报告结论必须记录：决策日期、实际样本量、证据链接、已知偏差、下一轮只修改的 1–2 个假设。**

## 8. 和 SEO 的关系：不要等待 SEO 自然流量才能完成实验

- Phase 0 的目标是**需求和行为验证**；可以从社群/定向访谈进入 landing，而不是等待新域名拿 Google 排名。
- SEO Playbook 的正式关键词评估仍须做；不能把上面 3 套 copy 当成已验证的高搜索量关键词。
- 健康内容是 Google 特别审慎的 YMYL 主题；正式可索引内容要有真实作者/医学审核、明确来源、适用边界和原创实用价值。参考：<https://developers.google.com/search/docs/fundamentals/creating-helpful-content>
- 后续是否投放广告、SEO 可收录页面数量、付费模型与产品体验，应分别根据转化数据判断，不要以短期 SERP 波动推断需求不存在。
