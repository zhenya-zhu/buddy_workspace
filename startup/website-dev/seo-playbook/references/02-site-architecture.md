# Phase 2：站点结构与页面策略

> 这一阶段决定"稀释"还是"聚焦"。绝大多数新站死在这里：页面很多、很杂，但没有一页是"最该被推荐的那一页"。

---

## AR-01 一个关键词一个域名，举全站之力

**优先级：P0**

**要点**：核心需求用独立域名承接，整站围绕它展开。不要在一个综合站里用某个内页去硬打一个独立需求。

**判定依据**：出自《【哥飞解读】为什么要一个关键词一个域名？》与《【哥飞解读】2025年谷歌算法排名因素变化》。原始数据源是 firstpagesage 的年度排名因素调研，哥飞逐年解读。**2025 版与 2024 版的关键变化**：

| 排名 | 因素 | 2024 | 2025 | 趋势 |
|---|---|---|---|---|
| 1 | 持续发布吸引人的内容 | 21% | **23%** | ↑ |
| 2 | 标题/元标签里的关键词 | 15% | **14%** | ↓ |
| 3 | 反向链接 | 28%→14% | **13%** | ↓↓ |
| 4 | 细分领域专长 | 14% | **13%** | ↓ |
| 5 | 用户参与度（停留、Last Click、跳出率） | 22%→11% | **12%** | ↑ |
| 6 | 新鲜度 | 0→6% | **6%** | 持平 |
| 7 | 移动端友好 | 5% | **5%** | 持平 |
| 8 | 可信度 | 0→5%→4% | **4%** | 持平 |
| 9 | 链接分布多样性 | 无 | **3%** | 新增 |

「细分领域专长」的含义是：谷歌不希望某个需求只被大站的一个内页满足，而希望有一个**专门做这件事的站**。一个需求通常等于一个关键词，所以 = 一个关键词一个域名。

**注意趋势方向**：反链权重三年从 28% 掉到 13%，但哥飞明确说"不代表新站上线不需要做外链了"，只是谷歌会从其他方面综合判断。真正在涨的是**内容满足度（23%）**和**用户参与度（12%）**——这两项决定了本站能否从"进前 20"走到"进前 3"。他用一个观察佐证："一个有一定 KD 的关键词，更少反链的网站拿到了更靠前的排名。"

新增的「链接分布多样性 3%」有实操含义：不只是首页要拿外链，**内页也要能拿到外链**。落到工具站上，就是不要把所有功能都堆在首页，要给长尾词单独做工具页，让每个工具页都能被用户分享传播。

原文引用的最佳答案："一个关键词一个域名，一个域名一个功能，一个功能一个主页，这样 SEO 权重高。"

**检查方式**：
1. 打开首页，问：**首页的 Title / H1 / 首屏，是不是全部围绕同一个核心需求？**
2. 检查 URL：核心需求是否落在根域名 `/`，而不是 `/tools/xxx`。
3. 检查内链：全站有多少条内链指向首页？（门槛：≥ 每页 1 条，通常通过 logo + 面包屑实现）
4. 反向检查：若一个域名下塞了 5 个不相关需求，且每个都不深——判定为"综合站稀释"，P0 不通过。

**不通过处置**：拆成多个域名分头做，或明确放弃非核心需求页。

## AR-02 页面深度 ≤ 3 次点击

**优先级：P0**

**要点**：任何页面从首页出发，最多点 3 次能到达。做不到就"把深度页面改成广度页面"。

**判定依据**：出自《【哥飞SEO教程】如何制作出SEO友好的网页？先从学习谷歌是如何理解我们网页开始》。原文："通常我们会说，页面深度不要超过 5 层，但哥飞建议，最好在 3 层内。也就是你要保证你网站的任何一个页面，都可以点击三次就能够到达。"

原文给出的参考形态：Toolify 的页脚结构（用页脚做全站广度入口）。

**检查方式**：
1. 用 Screaming Frog 爬全站 → `Crawl Depth` 列。
2. 筛 `Depth > 3` 的 URL，统计占比。
3. 检查页脚是否提供了分类/全量索引入口。

**通过阈值**：`Depth > 3` 的页面占比 = 0（或仅剩极少数新发布页 ≤ 1%）。

## AR-03 首页必须"列举最新内容"（收录加速器）

**优先级：P0**

**要点**：在首页放一个"最新内容"模块，持续输出内页链接，是加快收录最有效的手段——比 Sitemap 更有效。

**判定依据**：出自《【哥飞SEO教程】如何制作出SEO友好的网页？》原文有一段极重要的判断：

> "Sitemap 对于谷歌是一个建议，谷歌可以不听，或者部分听取。谷歌更喜欢通过链接去不断爬行探索网站。甚至哥飞目前最新的这个网站不到一个月收录十几万，压根就没有 Sitemap。方法就是在首页不断的列出最新的内容，同时有一个页面能够一页一页列出网站所有页面。"

同时《新上线的网站，如何快速让谷歌收录？》指出：生成几十万个页面的前提是"内链和网站地图"要做好，才能让搜索引擎发现所有内页。

**检查方式**：
1. 打开首页，找"最新 / Latest / New / Recently added"模块，确认链接是**真实 `<a href>`**（不是 JS 点击）。
2. 确认该模块随内容更新而更新（抓两次间隔 24 小时对比）。
3. 确认存在一个"全量索引页"（如 `/all`、`/sitemap` 页面），能从页脚一级进入。

**通过**：三项全为是。

**⚠️ 关键约束**：见 AR-04 与 AR-08——这个模块**只放标题和链接，绝不放正文全文**。

## AR-04 首页内容不得膨胀（红线）

**优先级：P0 —— 红线**

**要点**：首页的"最新内容"模块只能输出**标题 + 链接**。一旦把内页的正文/问答全文渲染到首页，关键词密度被稀释、语义跑偏，排名会直接崩。

**判定依据**：出自《【哥飞实操分享】一个真实的SEO失败案例》。原文复盘：

> 网站首页原本约 400 多个单词，某次发版后"最新问答列表模块把问题和回答全文都在首页输出了"，首页变成两三千个单词。"单词一多，就坏菜了，我的核心关键词的密度下降了。并且谷歌是懂语义分析的，一分析发现，你这个网站首页内容乱七八糟的，跟 GPT 4o 没多大关系了。于是谷歌的惩罚就来了，直接减少曝光，降低排名。"——**且下掉模块后仍未短期恢复**。

这是本清单里**唯一有完整事故复盘的红线**，权重极高。

**检查方式**：
1. 取首页可见正文（去导航/页脚/广告）统计单词数，与核心关键词出现次数一起算密度。
2. **对比法**：把首页正文中"非核心主题"的段落整段删掉，看核心关键词密度是否显著上升（>0.3 个百分点）。若是 → 已膨胀。
3. 检查 DOM：首页列表模块内是否包含 `<p>` 长文本；是否服务端输出了内页正文。
4. 回归测试习惯：任何改动首页模块的发版，发版前后各记录一次 GSC 曝光/点击基线。

**通过阈值**：首页正文 ≤ 500 词（除首页本身承载的长文型落地页外），核心关键词密度 ≥ 1%，且首页正文 80% 以上内容与核心需求直接相关。

> **⚠️ 这条是对照用的经验线，不是及格线。** 反例：`blackscreen.app` 全年 1000 万访问量、**整站只有 40 个单词**（而且因为黑底黑字，用户根本看不到这 40 个词），照样拿下 "Black Screen" 第一名（《一年一千万访问量的网站，只有40个单词》）。同一个词的 `blackscreen.space`（2023 年 6 月注册）排第二。
>
> 这说明**词数本身不是排名门槛，需求满足度才是**。这条阈值真正要防的是"首页被无关内容撑大、语义跑偏"（R3 那条事故），不是"首页必须写满 500 词"。**工具型首页，功能即内容，词数为 0 也可能及格**；内容型首页才需要看词数下限。
>
> 判断口诀：**先问"用户打开首页 3 秒内有没有得到他要的东西"，再问词数。** 顺序颠倒就会为了凑字数把首页写胖，反而踩 R3。

## AR-05 新站不要批量上页面

**优先级：P0 —— 红线**

**要点**：新域名一上线就灌几百上千个页面，是典型死法。

**判定依据**：出自《【哥飞SEO教程】新站批量化上页面，必死》，以及其姊妹篇《新站不批量上页面，那要怎么做页面呢？从对SEO祛魅开始！》。核心逻辑与新站没有权重基础有关：一堆没有竞争力、没有内链支撑、没有用户行为数据的页面同时出现，容易被判定为低质/采集。

**检查方式**：
1. 记录上线首周提交/可访问的 URL 总数。
2. **首周 URL 数 ≤ 20**（除"程序化 SEO"策略外，见 AR-07）。
3. 检查是否所有页面都已进入内链体系（无孤岛页）。

**通过**：首周页面数受控，且每一页都有明确的关键词目标和内链入口。

**例外**：程序化 SEO（AR-07）在**老域名**上可以一开始就上大量页面；新域名不行。

## AR-06 先收集关键词，再规划网站结构

**优先级：P1**

**要点**：结构不是先画导航再找词，而是先有一张关键词表，再让结构去承接这张表。

**判定依据**：出自《【哥飞SEO教程】先收集关键词，再规划网站结构》。逻辑：站点结构本质是关键词的层级化分组，先有词表才能避免"为了分类而分类"。

**检查方式**：
1. 是否有一张 ≥ 50 行的关键词表（词 / Volume / KD / CPC / KDRoi / 意图分类）？
2. 站点一级导航是否与词表的最大分组一一对应？
3. 每个内页是否都能在词表里指到一个具体词？（指不到的页 = 无目标页，应删或补词）

**通过**：无目标页数量 = 0。

## AR-07 程序化 SEO：量大是手段，不是目的

**优先级：P2**（进阶策略）

**要点**：用动态路由为每个参数组合生成一个页面（如每个 16 进制颜色码一页），靠内链 + 站点地图让搜索引擎发现全部内页。

**判定依据**：出自《新上线的网站，如何快速让谷歌收录？做网站为什么要生成几十万个页面？》原文举例：`ff0066` 这类颜色码，每个一页可生成 1600 多万页；实际不是生成静态文件，而是"用动态页面，根据不同的 url 路径参数显示不同的页面"。"一个页面可能一天只能带来 10 个访问，但如果你有 10 万个这样的页面，是不是每天就有 100 万个访问了。"

同时《【哥飞小课堂】用几个案例来讲解程序化SEO生成海量页面获取流量的方式》与《用三个案例来详细解释大型网站的SEO引爆点为什么是生成几十万个页面给搜索引擎收录》给出方法论。

**检查方式**：
1. 参数空间是否足够大（≥ 1 万组合）？
2. 每个组合是否有**真实存在的独立需求**（而不是无意义排列）？
3. 是否有全量索引页 + 分页 + 交叉内链（否则一半页面永不被发现）？
4. 页面之间内容重复度是否受控（模板相同但正文需差异化）？

**通过**：四条全满足，且站点已有一定权重基础。**新手第一个站禁用此策略。**

## AR-08 用户要什么就给什么页面，别默认做博客

**优先级：P1**

**要点**：页面类型要匹配搜索意图，不是"内容站就写博客"。

**判定依据**：出自《【哥飞SEO教程】别再继续做博客页了，正确的做法是用户要什么你就做什么页面》。配合 KW-03 第 4 步（用户要工具 / 列表 / 教程 / 模板 / 下载 / 计算器 / 答案）。

**检查方式**：对每个目标词，回看 SERP 前 10 的页面类型，统计占比最高的一种，作为你要做的页面类型；若你的页面类型与主流类型不一致，需要在"满足需求"上有明显优势，否则不通过。

## AR-09 已有排名后，新功能放首页还是内页

**优先级：P1**（迭代期）

**要点**：先守住已成立的页面，再做新增需求。判断新需求与主词的关系再决定位置。

**判定依据**：出自《网站已经有排名，新功能该放首页还是内页？》。原文给出的三步：`01 保留主词 → 02 判断需求 → 03 建立内页`，原则是"先做深，再做广"。

**检查方式**：
1. 若新功能与主词**同一意图** → 放首页（但受 AR-04 约束）。
2. 若新功能是**独立意图** → 建内页，并从首页/相关页内链过去。
3. 若新功能会显著改变首页语义 → 一律建内页。

**通过**：有明确判断记录，且首页改动前有 GSC 基线。

---

## 阶段出口

- [ ] 首页围绕单一核心需求，Title/H1/首屏一致
- [ ] 全站页面深度 ≤ 3
- [ ] 首页有"最新内容"模块（仅标题+链接）+ 全量索引页
- [ ] 首页正文 ≤ 500 词（工具型站不设下限，见 AR-04 备注），核心词密度 ≥ 1%
- [ ] 首周页面数 ≤ 20（非程序化 SEO）
- [ ] 每个页面都能在关键词表里指到一个词
