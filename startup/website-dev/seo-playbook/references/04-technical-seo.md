# Phase 4：技术 SEO（能不能被抓到、能不能被收录）

> 这一层的特点：**做错了是 0 分，不是扣分。** 页面做得再好，谷歌抓不到就是不存在。

---

## TS-01 必须后端渲染（红线）

**优先级：P0 —— 红线**

**要点**：所有需要参与排名的内容，必须在服务端输出的 HTML 里。不要依赖客户端 JS 渲染正文。

**判定依据**：出自《【哥飞SEO教程】如何制作出SEO友好的网页？先从学习谷歌是如何理解我们网页开始》。原文讲清了谷歌的抓取链路：

> "拿到一个网址后，程序发出一个 GET 请求，获取网址对应的 html 代码，这就是爬虫最主要做的事情。**注意，这里只是获取到了 html 代码，并没有去执行 html 代码。** 我们可以想到，如果你的网页是前端渲染的，那么拿到的就只是 html 模板，没有任何内容，那自然就无法参与排名。"

关于"谷歌会不会执行 JS"：

> "运行代码需要消耗额外的算力，谷歌只会给一些大网站有这样的优待，因为谷歌很需要那些大网站的内容。对于我们做的小破网站，谷歌不算浪费算力的。"

**检查方式**：
1. `curl -s https://yourdomain.com/page | grep "核心关键词"` —— 必须能命中。
2. 浏览器禁用 JavaScript 后打开目标页，正文是否完整可见。
3. 用 GSC 的「网址检查 → 查看已抓取的网页 → HTML」看谷歌实际拿到的 HTML 是否含正文。
4. Next.js 用 SSG/SSR（`getServerSideProps` / 静态导出），禁用纯 CSR；Nuxt / Astro 同理。

**通过阈值**：三项全通过。任一失败 → 不部署。

## TS-02 多语言必须换 URL（红线）

**优先级：P0 —— 红线**

**要点**：语言切换必须改变 URL。用 JS 在前端切语言 = 只有默认语言能被收录。

**判定依据**：同 TS-01 原文第三个问答：

> "为什么多语言不能用 js 切换？因为 js 切换不会改变网址，这就导致谷歌爬虫来的时候，只能抓取到一种语言的内容，也就只能参与一种语言的搜索排名。那么这个网页的多语言就相当于白做了。"

**检查方式**：
1. 点语言切换，URL 是否变化（`/es/`、`?lang=es` 都算变化；纯前端切换不算）。
2. 每种语言版本是否有独立的 `<title>` 与 `<h1>`，且是目标语言，不是英文。
3. 每种语言版本是否有自引用 `hreflang`（及 `x-default`）。
4. 语言版本之间是否有互相内链（语言切换器用 `<a href>` 而非 JS）。

**通过**：URL 变化 + 独立 TDH + hreflang 齐全。

## TS-03 语言版本用子目录，不用子域名

**优先级：P1**

**要点**：`example.com/es/` 优于 `es.example.com`。

**判定依据**：出自《再聊多语言：为什么不建议使用子域名而更建议使用子目录》，以及更早的《从一个月访问量7.8亿的网站告诉你子域名和子目录该如何选择》。核心逻辑：子目录继承主域权重，子域名需要重新积累。

**检查方式**：检查多语言 URL 结构。已是子域名的，评估是否值得迁移（有排名后迁移成本高，需 301 + 观察 3 个月）。
**通过**：新项目一律用子目录。

## TS-04 Sitemap 与 GSC 提交

**优先级：P1**

**要点**：Sitemap 是"建议"不是"命令"，但不能没有。小站可以靠 GSC 提交 + 内链代替。

**判定依据**：出自《【哥飞SEO教程】如何制作出SEO友好的网页？》：

> "Sitemap 对于谷歌是一个建议，谷歌可以不听，或者部分听取。谷歌更喜欢通过链接去不断爬行探索网站。"

以及《【哥飞解答】第一个出海站，要做什么？要怎么做？》：

> "如果你的网站页面数量不多，不用 sitemap.xml 也是可以的，只要到了 GSC，过两天就能够被收录了。"

**检查方式**：
1. `/sitemap.xml` 可访问、返回 200、`Content-Type` 正确。
2. 已在 GSC 提交，且「已发现网页数」与站内实际 URL 数偏差 < 10%。
3. Sitemap 内 URL 与 `lastmod` 真实（不要全部填当前时间）。
4. 若 Sitemap 报"无法抓取"，按《Google Search Console 提示站点地图 Sitemap 无法抓取怎么办？》排查（多为 robots.txt 拦截或返回 5xx）。

**通过**：三项达标；页面数 < 20 的小站可豁免 Sitemap，但必须完成 GSC 提交。

## TS-05 收录加速：去高爬取频率的站点发帖

**优先级：P1**

**要点**：新站收录最快的手段不是等，是**把链接放到谷歌爬虫高频光顾的地方**，让它进入待爬队列。

**判定依据**：出自《新上线的网站，如何快速让谷歌收录？》：

> "答案是去 V2EX 发帖介绍自己产品，然后留下网站链接。这个方法 10 年前就有用，现在更有用了，因为 V 站在谷歌的权重更高了。"

以及《【哥飞实操分享】一个真实的SEO失败案例》给出的验证方法：

> "我们在谷歌用 site 指令查询某个网站的页面收录情况时，可以选择把时间范围设置为 Past hour，通过这个方法可以看出谷歌爬虫是否经常来这个网站……V2EX 是一个很活跃的社区，时刻都在产生新的帖子，谷歌的爬虫为了不错过，就经常过来爬。"

**检查方式**：
1. 上线后 24 小时内：GSC 提交首页 + 到 2–3 个高频更新的社区发帖（V2EX、Reddit 相关 sub、Hacker News、Product Hunt）。
2. 48 小时后用 `site:yourdomain.com` 验证是否已被收录。
3. 若 72 小时仍未收录，用 `site:v2ex.com` + Past hour 确认目标社区确实被高频抓取，换一个更活跃的源。

**通过阈值**：48 小时内 `site:` 能查到 ≥ 1 个页面。**超过 7 天未收录 → 回到 TS-01 检查渲染。**

## TS-06 robots.txt：多语言站的正确拦截

**优先级：P1**

**要点**：多语言站的 robots.txt 常见错误是把不该拦的拦了，或把该拦的放开了（如参数页、搜索结果页、分页）。

**判定依据**：出自《【哥飞SEO教程】多语言网站 robots.txt 设置指南：如何正确阻止不希望被抓取的页面》。

**检查方式**：
1. 访问 `/robots.txt`，确认没有 `Disallow: /` 或误拦静态资源（`/cdn/`、`/*.js`）。
2. 确认语言目录未被整体拦截（除非该语言不打算做）。
3. 确认拦截了：内部搜索结果页、带 `?sort=` / `?filter=` 的重复参数页、`/cart`、`/admin`。
4. 用 GSC 的 robots.txt 测试工具实测 3 个关键 URL。

**通过**：核心语言页可抓、无价值页被拦、无语法错误。

## TS-07 Canonical 与出站 nofollow

**优先级：P1**

**要点**：Canonical 用错有坏处，要小心；站内外链默认 dofollow 传递权重，指向外部时通常设 nofollow。

**判定依据**：
- 《【哥飞SEO教程】再聊 Canonical 标签，用好有好处，用错有坏处，需要小心用》
- 《【哥飞SEO教程】如何制作出SEO友好的网页？》第八节：「一般站内链接都是 do follow 的，也就是会完全传递权重，而外链则为了不传递太多权重出去，我们会设置为 no follow。」

**检查方式**：
1. 每个页面是否有自引用 canonical（指向自己）。
2. 分页页面的 canonical 指向是否正确（不要全部指向第 1 页，除非确认要合并）。
3. 多语言版本的 canonical 指向**自身语言版本**，不要互相指向。
4. 统计每页出站外链数，超量或指向低质站点的加 `rel="nofollow"`。

**通过**：canonical 自引用无错、多语言不互相指向。

## TS-08 2026 年的分层现实：AISEO 与结构化数据

**优先级：P2**

**要点**：AI 搜索正在分流，但基础 SEO 仍是根；结构化数据要按当前支持情况写，不要照抄过时教程。

**判定依据**：
- 《以DeepSeek为例，哥飞跟你简单聊聊如何做AISEO》
- 《【哥飞SEO教程】谷歌下线 FAQPage，新页面还要不要写结构化数据？》——FAQPage 已被谷歌下线，继续写不会带来富媒体展示。
- 《【哥飞SEO教程】不要把 GSC 的提示当报错，提示跟预期一致就是正常现象，不用处理》——避免过度响应 GSC 提示。

**检查方式**：
1. 优先级判断：若站内基础项（渲染/收录/内链）未完成，**不要投入 AISEO**。
2. 结构化数据只写当前有效的类型（Article、Product、BreadcrumbList、Organization 等），不写已下线的 FAQPage。
3. GSC 出现"改进建议"类提示时，先判断是否与预期一致；一致则不处理，记录即可。

**通过**：无效结构化数据类型 = 0。

## TS-09 收录与抓取的日常验证

**优先级：P1**

**要点**：建立固定的收录巡检动作，而不是等出问题才查。

**判定依据**：出自《【哥飞实操分享】一个真实的SEO失败案例》（`site:` + `Past hour` 判断爬虫频率）与《【哥飞SEO教程】通过看 GSC 四级信号来看自己网站是否可能被谷歌惩罚》。

**检查方式**（建议每周一次，记入表格）：

| 检查 | 命令/位置 | 异常信号 |
|---|---|---|
| 是否被收录 | `site:yourdomain.com 关键词` | 结果数骤减 |
| 页面数是否异常 | GSC「已编入索引」 | 断崖式下跌 |
| 抓取频率 | `site:yourdomain.com` + Past hour | 长时间 0 条 |
| 曝光/点击 | GSC 效果报告 | 曝光跌 >30% |
| 手动操作 | GSC「安全性与手动操作」 | 出现任何处罚 |

**通过**：周检记录连续，异常能在 7 天内发现。
