# Phase 0–1：机会识别与关键词验证

> 结论先行：**关键词没选对，后面全白干。** 这一阶段的所有检查都是为了回答两个互相独立的问题——「有多少人在认真抢这个词」和「现在排在前面的有多强」。

---

## KW-01 需求来源：用"修饰词 × 品类"矩阵批量挖需求

**优先级：P0**

**要点**：不要凭灵感找需求。用一批固定的"功能修饰词"去乘目标品类，批量生成候选需求，再筛。

哥飞给出的 51 个高价值修饰词（原文完整列出，可直接复用）：

> Translator、Generator、Example、Convert、Online、Downloader、Maker、Creator、Editor、Processor、Designer、Compiler、Analyzer、Evaluator、Sender、Receiver、Interpreter、Uploader、Calculator、Sample、Template、Format、Builder、Scheme、Pattern、Checker、Detector、Scraper、Manager、Explorer、Dashboard、Planner、Tracker、Recorder、Optimizer、Scheduler、Converter、Viewer、Extractor、Monitor、Notifier、Verifier、Simulator、Assistant、Constructor、Comparator、Navigator、Syncer、Connector、Cataloger、Responder

**判定依据**：出自《养网站防老第1步，挖掘出第1个需求》。原文以 Translator / Generator 为例演示：用 Semrush 查修饰词 → 看 Keyword Variations（变种）→ 看 Related Questions → 看 Related Keywords，逐层扩张候选池。核心逻辑是这类词天然对应"工具型需求"，落地成本低、意图明确。

**检查方式**：
1. 在 Semrush 输入修饰词，国家先选目标市场（美国 / 德国 / 日本等，不要默认印度——原文明确说"印度太穷了"换德国）。
2. 打开 **Keyword Variations** 页，用筛选器设 `KD 0–29`、`CPC ≥ 0.1`、按 Volume 降序。
3. 记录候选词 ≥ 30 个，进入 KW-02。
4. 若某词的变种/相关词数量极少（<50），说明该需求过窄，标记为"练手级"，不投入主力。

**不通过处置**：候选池不足 30 个 → 换修饰词或换品类，不要硬做。

## KW-02 KDRoi 排序：用公式量化"值不值得投"

**优先级：P0**

**要点**：哥飞自创公式，用来在候选池里优中选优。

```
KDRoi = Volume × CPC / KD
```

**判定依据**：出自《养网站防老第1.5步：用一个公式来判断关键词是否值得做》。原文逻辑：离钱越近的词价值越高（CPC 代理"离钱近"），同一关键词在发达国家价值更高（所以必须先定国家）。

**检查方式**：
1. 在 Semrush 对修饰词设筛选：`Volume ≥ 600`、`KD 0–29`、`CPC > 0.1`，并**排除含 "near me" 的词**（本地服务意图，不适合纯线上站）。
2. 导出 CSV，保留 `Keyword / Volume / KD / CPC` 四列。
3. 新增一列 `=B2*D2/C2`（Volume×CPC/KD），降序排序。
4. 取 Top 10–20 进入 KW-03 人工复核。

**通过阈值**：进入下一轮的数量 ≥ 10 个。**低于 10 个不要勉强开站**——说明这个修饰词/品类已被充分覆盖。

**注意**：KDRoi 高不代表能做。原文的 Top 榜里出现过 `katy hearn macro calculator`（KD=0、Volume=1900、CPC=0.98）这类**纯人名长尾**，量太小、不可扩展，属于"数字好看但不能做成站"的陷阱。必须过 KW-03。

## KW-03 SERP 人工复核：打开前 10，别只看分数

**优先级：P0**

**要点**：工具分数只回答一半问题。必须打开真实搜索结果，看前排到底是什么页面。

哥飞给的 5 步检查法：

| 步骤 | 看什么 | 判断 |
|---|---|---|
| 1 | 搜索量 | 太小不一定不能做，但要算投入产出；练手可做，赚钱要慎 |
| 2 | `intitle:` 数量 | 标题供应量少 = 专门做这个词的页面少 = 有机会 |
| 3 | 前 10 结果类型 | 是首页 / 栏目页 / 工具页 / 文章页 / 顺手提到的内页 |
| 4 | 页面是否满足需求 | 用户要工具、列表、教程、模板、下载、计算器还是答案？前排做好了吗？ |
| 5 | 决定打法 | 核心需求 → 首页打；长尾 → 内页打；需求分散 → 拆成一组页面 |

**判定依据**：出自《【哥飞SEO教程】KD 很高的词也能做，先看真实网页供应量》。原文明确：`KD` 只回答"前排页面有多强"，`KGR/intitle` 才回答"有多少页面在认真抢"，两者不一定同步，只看一个数字必然误判。

**检查方式（可直接照做）**：
1. Google 搜 `intitle:"关键词"`，记数量 N_title。
2. 逐个打开前 10 条，记录：页面类型、所属站点规模（用 Similarweb 看月访问）、页面是否真的解决该需求。
3. **红线判定**：若前 3 名包含维基百科、时代周刊类超大站首页/权威页，且你的站是全新域名 → 直接放弃（原文案例：`meme generator` 因 `time.com` 排第一而放弃；`meme generator` 的 KD 从 26 飙到 93）。
4. **机会判定**：若前 10 多为"顺手覆盖的内页"、页面聚焦度差、体验一般 → 标记为可打，走 KW-05 的"首页打内页"策略。

**通过阈值**：前 10 中至少 5 条是**内页**（非首页），且至少 3 条**没有专门为这个词做页面**。达不到就不要做。

## KW-04 KGR 量化供应量（新词与蓝海词必用）

**优先级：P0**（做新词时强制）

**要点**：

```
KGR = allintitle 结果数 / 关键词月搜索量
```

**判定依据**：出自《【哥飞SEO教程】使用KGR公式来量化新词，寻找蓝海词》。原文示例：`ai image editor` 的 `allintitle` = 1790，月搜索量 20 万，KGR = 0.00895。原文结论：**KGR < 0.25 就是值得做的词**。

为什么必须用它：新词的 KD 在 Ahrefs / Semrush 里查不到（工具还没收录这个词），无法用常规指标判断竞争度，KGR 是唯一可量化的替代指标。

**检查方式**：
1. Google 搜 `intitle:"关键词"`（原文建议**用 intitle 而非 allintitle** 来算，理由是两者在部分词上差异较大，intitle 更贴近真实竞争面）。
2. 月搜索量优先取 Google Ads 后台的官方数据（原文做法），其次 Semrush。
3. 算 KGR。
4. 交叉验证：Google Trends 看趋势是否平稳/上升。**季节性词要单独标记**（原文在 `phone number generator` 案例中专门查了 Trends 排除季节性）。

**通过阈值**：
- `KGR < 0.25` → 可做
- `KGR < 0.05` → 优先做（蓝海）
- `KGR > 0.25` → 需要 KW-05 的"举全站之力"策略才有机会，新手放弃

## KW-05 打法匹配：首页打内页

**优先级：P0**

**要点**：同一个词，用什么页面去打，决定成败。哥飞的核心打法——**用你的首页，去打别人的内页**。

**判定依据**：出自《【哥飞SEO教程】KD 很高的词也能做，先看真实网页供应量》与《【哥飞解读】为什么要一个关键词一个域名？》。后者的理论支撑：谷歌排名因素中「细分领域专长」占 13%（2025 版，2024 为 14%）；第一位是"持续发布吸引人的内容"23%，第二位"标题里的关键词"14%。谷歌不希望某个需求只靠大站的一个内页满足，而希望有专门做这个需求的网站。

**检查方式**：

| 场景 | 打法 | 落地形态 |
|---|---|---|
| 前排是大站内页、KD 中等或偏高 | 首页打 | 独立域名，首页围绕该词，工具+说明+FAQ+案例+内链全部集中 |
| 前排已是强首页、且是多年老站 | 放弃或换长尾 | 用长尾表达反向吃主词（见 KW-06） |
| 需求分散成多个子意图 | 首页 + 一组内页 | 首页吃主词，内页吃长尾，内页反向内链回首页 |
| 纯练手第一个站 | 内页即可 | 目标只是收录 + 进前 10，不追求流量 |

**通过**：能明确写出"我用首页/内页打哪个词，对手是什么页面类型"。写不出来 = 没想清楚，不许开工。

## KW-06 新词先发优势 vs 老词长尾包抄

**优先级：P1**

**要点**：新词靠速度，老词靠角度。

**判定依据**：
- 新词：《新词来了时，请抓住先发优势，尽快发布》——新词刚出现时 KD 查不到，先发的站能靠"时间"这一维度拿到排名。
- 老词：《【哥飞SEO教程】新词老词都可以做，老词可以用长尾表达反向吃主词》——不正面打主词，先用长尾页积累相关性和权重，再反向吃主词。
- 新手定位：《老手可以去做难而正确的事情，新手只需要去追热点追新词就行》。

**检查方式**：
- 判断词龄：Google Trends 的曲线起点、`intitle` 结果里最早页面的发布时间（可用 Wayback Machine 看）。
- **词龄必须和 KD 一起看，这是原文给出的硬比较**："一个 KD 为 50 的半年内出现的词，比一个 KD 为 30 的一年前出现的词更容易拿到排名。"（《【哥飞带你读】Ahrefs研究：网页从上线开始算起拿到排名需要多久时间》）
  - 所以选词排序不能只用 KDRoi = Volume × CPC / KD，必须加一列「词龄」。**半年内的词，KD 可放宽约 20；一年以上的词，KD 要更严**（此为按原文比较关系推导的经验线）。
  - 实操：Semrush 查 KD 时同时看 "Keyword Difficulty" 旁的 SERP 数据更新时间，以及 `intitle` 结果中最新页面的发布日期。
- 若是新词 → 检查"从发现到上线"的时长，目标 ≤ 72 小时（原文多个案例中，新词站的窗口期以天计）。
- 若是老词 → 检查是否规划了 ≥ 5 个长尾内页，且这些内页内链回主目标页。

**通过**：每个目标词都有明确的"新词/老词"标记、词龄、以及对应打法；且 KD 判断已按词龄做过修正。

## KW-07 变现路径预判（离钱距离）

**优先级：P1**

**要点**：选词阶段就要想清楚怎么收钱，否则流量来了也是白流。

**判定依据**：出自《养网站防老第1.5步》——"离钱越近的关键词，价值越高"，CPC 是其代理指标；《再聊小词：不妨看看CPC，有价值的小词也是值得做的》。原文在 KW-01 案例中直接否掉过一个高搜索量的词：**"不能做，因为不好变现，连广告都没办法放，也没办法接入支付"**。

**检查方式**：对每个候选词回答三问：
1. 能不能放 AdSense？（有商业意图、非敏感、非纯娱乐）
2. 有没有可订阅/可付费的功能点？（工具类优先）
3. CPC 是否 ≥ 0.1 美元？（低于此值说明广告主不认这个需求）

**通过**：三问中至少 2 个为"是"。只满足 0 个 → 放弃，无论搜索量多大。

## KW-08 第一个站的特殊标准（练手站）

**优先级：P1**（仅第一个站）

**要点**：第一个站的目的不是赚钱，是跑通流程。

**判定依据**：出自《【哥飞解答】第一个出海站，要做什么？要怎么做？》。原文明确：
- 成功标准只有两条：**网站能上线**、**目标关键词进谷歌前 10**（不要求第一、不要求前三）。
- 选词标准：Ahrefs 中 **KD < 10**，且**所需外链网站数 < 10**；**不必关心搜索量，月 100 搜索量也可以**。
- 时间预期：约一周左右靠外链推进进入前 10。
- 递进路线：第 1 站（上线+前10）→ 第 2 站（日 100 点击）→ 第 3 站（日 1000 点击）。

**检查方式**：立项文档里写清本站属于第几站、对应的量化目标。若第一站就选了 KD>30 的词，属于典型启动失败。

**通过**：目标与站点序位匹配。

## KW-09 搜索意图拆解（对应「养网站防老第2步」）

**优先级：P0　执行顺序：必须在 KW-02 之后、KW-05 定页面形态之前完成**

**要点**：词选出来了不等于知道该做什么页面。同一个词背后可能是工具需求、教程需求、地域需求、代码库需求，做错形态就满足了错误的意图。

**判定依据**：出自《养网站防老第2步：分析搜索意图》——原文是「养网站防老」系列的第 2 步，逻辑上承接第 1 步挖需求、下接第 3 步做页面。原文以 `phone number generator` 为例：先收集谷歌下拉推荐词，再用 AI 逐词分析意图，最后让 AI 反推"这种意图该做什么网页"。

**检查方式**（原文给的可复现流程）：
1. **收集下拉词**：在谷歌输入目标词，把光标分别放在**词首、词中每个词后、词尾**四个位置（原文发现"光标放在不同位置，出来的相关词也不全一样"），全部记录。原文一次拿到 40 个推荐词，去重后 27 个。
2. **AI 拆意图**：把词表交给模型，逐个输出"关键词 → 搜索意图"。对不清晰的词追问一层。
3. **按意图聚类**：把 27 个词归成 3–5 类意图（例：`...for youtube` = 要能过平台验证的号；`...python` = 要代码库；`...malaysia` = 要本地格式）。
4. **每类意图对应一种页面形态**，再回到 KW-05 决定哪一类用首页承接、哪几类用内页吃长尾。
5. 检查页面实际内容是否命中**主导意图**：把首页首屏当成一个陌生用户，问"我要的是不是立刻得到"。

**通过阈值**：
- 每个候选词都有 ≥ 3 类意图标注，且**主导意图明确**（占比最高那一类）。
- 首页方案能覆盖主导意图，而非覆盖搜索量最大的那个子词的次要意图。
- 反例判定：若页面主体是"介绍这个工具是什么"（教程意图），但词的意图是"给我一个能用的工具"（工具意图）→ 不通过。

## 阶段出口

进入 Phase 2 前，必须能回答：

- [ ] 目标关键词（1 个主词 + 若干长尾）已确定，且有一个词是"全站围绕它转"的
- [ ] KDRoi 已算，且在候选池里排名靠前
- [ ] `intitle` 供应量已记录，前 10 SERP 已人工看过并截图
- [ ] 词龄已标注（新词/老词），KD 已按词龄修正
- [ ] 搜索意图已拆解到 ≥ 3 类，主导意图明确，且页面形态与主导意图匹配
- [ ] 打法是"首页打"还是"内页打"已明确
- [ ] 变现路径已明确（广告 / 订阅 / 佣金）
- [ ] 若为第一个站，KD 与所需外链站数均已达标
