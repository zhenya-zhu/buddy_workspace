# 体态康复 — 项目思考总览

> 整理日期：2026-11-07。范围：当前可见项目讨论，以及仓库已合并的 2026-10-28～29 产品规划。  
> 这是项目思考汇总，不是逐字对话导出、临床指南或上线证明。现有材料未提供用户实验、专业审核、收款或部署完成的证据，相关状态均保持待验证。  
> 标注：[原文] 明确的用户要求或具名来源的转述；[推断] 候选产品方案与判断；[工程] 实现及维护约束。

## 1. 一句话方向

[推断] 面向长期使用电脑的人，帮助用户选择容易执行的日常工作间歇活动，记录当次与次日体验，形成愿意重复的活动习惯。先通过一个小型 Web 产品验证价值，再决定 App 和更多场景。

“体态康复”是本项目的归档名，不是已经确定的对外品牌、医疗用途或疗效承诺。现有细分方案暂称 Desk Mobility。

## 2. 已明确的用户要求 [原文：项目讨论]

- 面向全球用户，考虑英文及后续多语言。
- 需要符合法规；产品不涉及诊断。
- 创业初期切入一个较小领域，验证后逐步扩大。
- 同时考虑用户转化、UX、SEO 和长期产品体验。
- 可以用多个入口测试不同文案，连接共享核心体验。
- 利用康复方法研究和个人观察提出产品问题，并持续保存项目思考。
- 本目录按用户要求建立于 ideas/体态康复/，作为项目想法的集中入口。

全球定位是方向；首发国家、语言、适用功能和运营范围仍需单独确定。其他功能、价格和人群选择见下文，不能全部当作用户已确认的决定。

## 3. 为什么先收窄 [推断]

最初探索包含全身体态/肌骨自查、人体图或 3D 标记、照片分析、解释关联因素、推荐动作与计划。这些想法保留为历史探索。

当前明确排除诊断。候选第一市场收窄为英语软件开发者、远程知识工作者的工作间歇活动场景，先验证“理解 → 开始 → 完成 → 返回 → 持续使用”。

这个人群尚未通过实际访谈与商业验证。选择它的理由是情境较集中、可能通过相似渠道触达、适合短时 Web 体验；理由仍需反例检验。

## 4. 项目目前的思考结构

| 层次 | 当前方向 | 尚待证明 |
|---|---|---|
| 用户问题 | 内容太多、难选择、难坚持、缺少连续记录 | 哪个问题最重要，是否值得切换现有工具 |
| 核心价值 | 减少选择与开始成本，帮助建立可重复习惯 | 用户是否理解、是否愿意回来 |
| 产品闭环 | 一次短体验 + 次日反馈 + 七天回顾 | 是否优于用户现有的视频、计时器或纸笔 |
| 获客 | SEO 内容积累 + 小规模招募/定位实验 | 哪些渠道带来会使用和留存的人 |
| 商业 | 先免费完整体验，后测试持续支持服务 | 是否真实付款、履约经济性是否成立 |
| 内容 | 少量定义清楚、经审核的活动与教育 | 审核资源、内容适用性及风险处理 |
| 扩张 | 更多场景、国家、语言、App | 每次扩张的增量价值与成本 |

## 6. 当前建议的第一步 [推断]

先确定一个人群、一个具体任务和首发服务范围；访谈实际用户；做两版定位入口与一个可操作原型。运动内容未完成专业审核时，先验证不含运动指导的需求/记录流程。

早期共享系统可以很小。先验证一次任务和重复使用，再自动化稳定流程；活动数量、复杂推荐、全身范围与原生 App 均按证据推进。
