## 2. Phase 0 具体指什么

产品 Phase 0 是投入完整系统前，验证需求、首次价值和重复价值的探索期。它不同于 SEO Playbook 的 Phase 0–7，也不同于工程 M0–M7。

| 阶段 | 主要问题 | 最小产物 | 推进所需证据 |
|---|---|---|---|
| 0A 问题与切入 | 谁需要，为什么会换现有方式？ | 一页 Brief、访谈、替代方案与搜索意图 | 真实场景、渠道、付出与反例 |
| 0B 首次价值 | 用户是否理解且能独立完成？ | 两版定位入口与一个原型 | 理解/完成时间、卡点与修改记录 |
| 0C 重复与付款 | 为什么回来，愿否为交付付款？ | 小批量人工支持、七天记录、清楚报价 | 成熟队列的返回、付款、退款及工时 |
| Web MVP | 哪些稳定步骤值得自动化？ | 小型完整网站与必要持久化 | 真实交付和发布/内容/隐私条件 |
| 增长与扩张 | 哪个渠道、场景或平台值得投入？ | 小规模增量实验 | 转化、留存、成本和增量收益 |

原型和工程 PoC 可并行，但工程完成不证明需求成立。缺少运动审核时，0A/0B 可以继续做不含运动指令的验证。

## 3. 第一轮候选实验

1. **8–12 次问题访谈**：实际情境、现有替代、未解决部分和代价；与关键词/竞争页面调研并行。
2. **5–8 人可用性**：先检查两版定位是否容易理解、共享原型是否能独立完成。
3. **内容与运营前置审核**：一项活动即可起步；专业审核、适用市场、同意/退出、数据恢复/删除需要就绪。
4. **20–30 人小批量七天体验**：允许披露的人工支持，逐人按完整窗口观察；后入组者不能被迫缩短。
5. **回顾与付费试验**：真实交付免费回顾，再测一个有清楚内容、期限与退款方式的报价。
6. **继续/调整/停止**：一次主要修改 1–2 个假设，不用加功能掩盖未找到的需求。

这些规模是此前提出的探索批次，不是统计保证、临床试验设计或固定行业标准；“两周”也是安排示例，完整观察随招募和审核进度延长。

## 4. 指标与判断线

| 要观察什么 | 应记录什么 | 避免的误判 |
|---|---|---|
| 理解与开始 | 入口来源、去重访问/开始人数、误解 | 点击多就有产品价值 |
| 首次完成 | 行动与反馈完成数、所有开始者、退出和缺失 | 隐藏安全退出提高完成率 |
| 次日返回 | 到期用户中实际回来者 | 愿意回来等于已经回来 |
| 持续记录 | D0–D6 记录天数、实际活动次数、D7 回顾访问 | 记录多等于临床有效 |
| 付费 | 看到报价、付款、退款、取消、履约 | 几笔订单证明最优价格或市场匹配 |
| 可运营性 | 工时、审核与支持成本、投诉和处理 | 托管便宜等于整体经济性成立 |

此前候选参考线为：20–30 人中有 6–8 人完成至少五个记录日、2–3 人实际付款，以及首访完成者中至少一半表达次日意愿。它们仅供早期方向判断；次日意愿仍需实际行为补证，不是正式成功阈值或医疗功效结论。

分渠道与入组日期报告分子、分母、缺失和观察期；没有到期的用户单列。熟人样本不能代表冷启动 SEO 用户。个人自评变化是描述性信息，不是因果疗效证据。

## 7. 后续记录格式 [工程]

每轮追加：日期、问题、假设、实验、预先判断线、证据链接、实际样本/窗口、反例与限制、决策、下一步。个人原始数据放受控私有位置，这里只保存可公开汇总。

继续：有重复价值且能交付，下一步只自动化已清楚的流程。调整：明确瓶颈在定位、任务、提醒、内容还是成本后再改。停止/转向：需求不成立、运营边界不可行或交付成本无法支撑时收缩，不以沉没开发成本作为继续理由。
